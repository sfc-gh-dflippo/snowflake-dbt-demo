Snowflake Migration Plugin

An AI-powered plugin that guides you through end-to-end database migration to Snowflake. It provides an interactive, conversational workflow — from connecting to your source database through deployment, data migration, and validation.

Supported sources: SQL Server, Amazon Redshift, Oracle

Quick Start

1. Launch the plugin

cortex --plugin-dir /your/path/ending/with/plugin/

Dependencies (uv, scai) are installed automatically on first launch.

2. Start migrating

"Migrate my database to Snowflake"

The agent configures the session, detects where you are in the migration, and picks up from there. You can also jump to any specific skill at any time.

Migration Workflow

The plugin guides you through six stages. At every stage the agent detects your progress and resumes where you left off.

StageWhat happens
1. ConnectSet up a connection to your source database (SQL Server or Redshift)
2. InitCreate a migration project
3. RegisterExtract DDL/code from the source database, or import local SQL files
4. ConvertTranslate source SQL into Snowflake SQL via SnowConvert
5. AssessGenerate assessment reports (deployment waves, object exclusions, dynamic SQL patterns, ETL analysis)
6. MigrateDeploy objects, migrate data, validate, and fix — wave by wave

A progress checklist is shown each time you start a session:

✅ 1. Connect          — Connected to SQL Server
✅ 2. Init             — Project initialized
✅ 3. Register         — 342 objects registered
◐  4. Initial Conv    — 280/342 converted
⬚  5. Assess          — Not run
⬚  6. Migrate Objects — 0/120 tables deployed

Skills

The plugin is organized as a skill tree — a hierarchy of Markdown instructions that tell the AI agent what to do at each stage. The root skill detects your project state and routes to the right sub-skill automatically. You can also ask for any skill directly.

Setup Skills (Steps 1–5)

SkillWhat it does
connection Walks you through connecting to SQL Server or Redshift — gathering credentials, testing the connection, and saving it for reuse.
register-code-units Gets source code into the project. Choose between extracting DDL/code from a live database or importing local .sql files from a directory.
convert Runs SnowConvert to translate your source SQL to Snowflake-compatible syntax. Produces converted files, reports, and a summary of EWIs (Early Warning Issues) by severity.
assessment Generates an interactive HTML assessment report. Includes deployment wave planning (dependency-aware ordering), object exclusion detection (temp tables, staging, deprecated), dynamic SQL pattern analysis, and SSIS/ETL package analysis.

Code Conversion Skills (Step 6)

SkillWhat it does
migrate-objects The main deploy loop. Gets the next dependency-ready object, then dispatches to the appropriate action: tables are deployed and data-migrated, views are deployed, functions and procedures go through a deploy–test–fix cycle. Repeats until all objects in the current wave are done.
baseline-capture Captures the output of source stored procedures and functions to use as test baselines. Supports two paths: parsing real query logs (CSV of EXEC/CALL statements) or AI-assisted test case generation when no logs are available.
rule-engine Manages reusable migration rules stored in Snowflake. Rules encode known source-to-Snowflake fix patterns (regex or AI-guided). Sub-skills: search (find rules for a SQL file), apply (run matched rules on local files), extract (create a rule from a code fix or git history), propagate (find all code units a rule applies to and batch-apply).

What You Can Ask

You don't need to follow the prescribed path — you can ask for any capability at any time.

Status & Navigation

  • "What is the current state?" — shows the progress checklist
  • "What should I work on next?" — returns the next dependency-ready object
  • "Continue" — picks up the prescribed migration path

Setup

  • "Connect to my SQL Server database"
  • "Extract objects from the source"
  • "Import SQL files from ./my-scripts/"
  • "Convert my source code"

Assessment

  • "Run a full assessment"
  • "Generate deployment waves"
  • "Identify temporary and staging objects"
  • "Analyze dynamic SQL patterns"
  • "Assess my SSIS packages"

Migration

  • "Deploy tables"
  • "Migrate data"
  • "Deploy and test the next function"
  • "Capture baselines for dbo.GetCustomerOrders"

Rules

  • "Search rules for this file"
  • "Apply all matched rules"
  • "Extract a rule from my last fix"
  • "Propagate this rule across the project"

Prerequisites

  • Snowflake account with a connection configured in ~/.snowflake/connections.toml
  • Source database accessible from your machine (SQL Server or Redshift)

All other dependencies (uv, scai, Python packages) are installed automatically by the plugin on first launch.

Troubleshooting

  • Plugin fails on startup — Check plugin/logs/install-dependencies.log. The install hook requires Homebrew (macOS/Linux) or winget (Windows).
  • scai not found — Run the install hook manually: plugin/hooks/install-dependencies, or install via Homebrew: brew install --cask snowflakedb/snowconvert-ai/snowconvert-ai.
  • Snowflake connection errors — Verify your connection in ~/.snowflake/connections.toml and make sure the name matches what you provided during setup.
  • Agent seems lost — Say "What is the current state?" to reset context. The agent re-reads project status and shows the progress checklist.
